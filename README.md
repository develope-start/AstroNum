# ასტრო — ნატალური, სინასტრიული და ტრანზიტული რუკების საიტი

Next.js 14 + TypeScript აპლიკაცია, რომელიც ითვლის ასტროლოგიურ ნატალურ, სინასტრიულ და
ტრანზიტულ რუკებს და აწვდის ქართულ ინტერპრეტაციას — ყველაფერი ერთ გვერდზე, გვერდის
დატოვების გარეშე.

## რა არის შიგნით

- **გამოთვლის ძრავა** (`src/lib/astro/`) — პლანეტების გეოცენტრული პოზიციები
  `astronomy-engine`-ის მეშვეობით (ზუსტი, ღია კოდის ასტრონომიული ბიბლიოთეკა,
  იგივე კლასის სიზუსტისა, რასაც სერიოზული ასტრო-სერვისები იყენებენ), ასცენდენტისა
  და MC-ის გამოთვლა (ვალიდირებულია მზის ამოსვლა/კულმინაციაზე), სამი სახლთა სისტემა
  (Whole Sign, Equal, Porphyry), მაჟორული ასპექტები.
- **გეოკოდირება** (`src/lib/astro/geo.ts`) — OpenStreetMap Nominatim-ით ადგილის
  სახელიდან კოორდინატებამდე, `tz-lookup`-ით კოორდინატებიდან დროის ზონამდე,
  `luxon`-ით კი ისტორიულად ზუსტი UTC-ოფსეტი (მათ შორის ძველი ზაფხულის დრო).
- **ინტერპრეტაცია** (`src/lib/interpretations/`) — ქართული ტექსტის გენერატორი
  პლანეტა/ნიშანი/სახლი/ასპექტების მიხედვით.
- **ავთენტიფიკაცია** — JWT + bcrypt, HTTP-only cookie. `USER` და `ADMIN` როლები.
- **კაბინეტი** — რეგისტრირებულ მომხმარებელს შენახული აქვს ყველა მისი რუკა
  (ნატალური/სინასტრია/ტრანზიტი) ინტერპრეტაციასთან ერთად.
- **ადმინის პანელი** (`/admin`) — მხოლოდ `ADMIN` როლისთვის: ყველა რეგისტრირებული
  მომხმარებელი და მათ მიერ გამოთვლისას შეყვანილი ყველა მონაცემი (სახელი, დაბადების
  თარიღი/დრო/ადგილი).
- **სტუმრის რეჟიმი** — დაურეგისტრირებელი მომხმარებლის შედეგი ინახება მხოლოდ მისივე
  ბრაუზერში (`localStorage`), 12 საათით. ბაზაში არაფერი ინახება, სანამ ანგარიშზე არ
  შევა და აქტიურად არ დააჭერს „შენახვა კაბინეტში".

## საწყისი გაშვება (დეველოპმენტი)

```bash
npm install
cp .env.example .env
# .env ფაილში შეავსეთ JWT_SECRET (გენერირება: openssl rand -base64 48)
# და ADMIN_EMAIL / ADMIN_PASSWORD — თქვენი, როგორც საიტის შემქმნელის, ანგარიშისთვის
# რეალური ელფოსტებისთვის დაამატეთ APP_URL, RESEND_API_KEY და EMAIL_FROM

npx prisma migrate dev --name init   # ქმნის dev.db (SQLite) ფაილს სქემით
npm run seed:admin                    # ქმნის თქვენს ADMIN ანგარიშს

npm run dev
# გახსენით http://localhost:3000
```

> **შენიშვნა:** `npx prisma generate`/`migrate` ინტერნეტიდან ჩამოტვირთავს პატარა
> ბინარულ ფაილს (query engine). ეს ჩვეულებრივ გარემოში პრობლემა არ არის — საჭიროა
> უბრალოდ ჩვეულებრივი წვდომა ინტერნეტთან დეველოპმენტის მანქანაზე.

## დეპლოი პროდაქშენში

1. **ბაზა.** SQLite კარგია ტესტირებისთვის, მაგრამ რეალურ საიტზე გამოიყენეთ
   PostgreSQL (მაგ. Supabase, Neon, Railway — ყველას აქვს უფასო ტიერი დასაწყისისთვის).

   გახსენით `prisma/schema.prisma`, იპოვეთ სტრიქონი:
   ```
   provider = "sqlite"
   ```
   და შეცვალეთ **მხოლოდ ეს ერთი სიტყვა** — არაფერი სხვა არ შეეხოთ ამ ფაილში:
   ```
   provider = "postgresql"
   ```
   შემდეგ `.env`-ში `DATABASE_URL`-ის ადგილას ჩასვით თქვენი PostgreSQL-ის
   ნამდვილი მისამართი (Neon/Supabase-დან დაკოპირებული, არა მაგალითი).

2. **ჰოსტინგი.** ყველაზე მარტივია [Vercel](https://vercel.com) (თავად Next.js-ის
   შემქმნელები) — უბრალოდ დააკავშირეთ GitHub რეპოზიტორია. ალტერნატივები:
   Render, Railway, ან ნებისმიერი სერვერი, სადაც Node.js 20+ გაქვთ.

3. **გარემოს ცვლადები** ჰოსტინგის პანელში მიუთითეთ იგივე, რაც `.env.example`-შია:
   `DATABASE_URL`, `JWT_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `APP_URL`,
   `RESEND_API_KEY`, `EMAIL_FROM`.

4. **დომენი.** ჰოსტინგის პანელიდან მიაბით საკუთარი დომენი (მაგ. astro.ge).

5. დეპლოის შემდეგ ერთხელ გაუშვით `npm run seed:admin` (ან ხელით შექმენით ანგარიში
   და მონაცემთა ბაზაში როლი `ADMIN`-ზე შეცვალეთ) — ეს არის თქვენი, საიტის
   შემქმნელის, სპეციალური შესვლა.

## ხშირი შეცდომები დაყენებისას

**`the current connector does not support enums`** — ეს ძველი ვერსიის ფაილებში
ხდებოდა (Prisma-ს სქემაში enum ტიპები SQLite-ს არ ესმის). გასწორებულია ამ
არქივში — თუ ეს ხედავთ, ჩამოტვირთეთ ახალი არქივი და დაიწყეთ თავიდან.

**`the URL must start with the protocol postgresql:// or postgres://`** —
`.env` ფაილში `DATABASE_URL`-ის მნიშვნელობა ან ცარიელია, ან არასწორადაა
ჩასმული. გახსენით `.env`, დარწმუნდით, რომ ზუსტად ასე გამოიყურება (ტირეებში,
რეალური მისამართით):
```
DATABASE_URL="postgresql://username:password@host/dbname?sslmode=require"
```

**`Can't reach database server at 'localhost:5432'`** (`npm run seed:admin`
გაშვებისას) — ეს ხდებოდა იმიტომ, რომ ეს სკრიპტი Next.js-ის მექანიზმის გარეთ
მუშაობს და `.env` ფაილს ავტომატურად ვერ კითხულობდა. გასწორებულია ამ არქივში.
თუ მაინც გხვდებათ: დარწმუნდით, რომ `.env` ფაილი ზუსტად პროექტის ძირშია
(იმავე საქაღალდეში, სადაც `package.json`) და რომ იქ ნამდვილი `DATABASE_URL`
წერია, არა მაგალითი.

**საიტი იტვირთება, მაგრამ რუკის გამოთვლა/კაბინეტი არ მუშაობს** — ჩვეულებრივ
ეს ნიშნავს, რომ `npx prisma migrate dev` (ან `migrate deploy`) წარმატებით არ
დასრულებულა. დაბრუნდით და თავიდან გაუშვით ეს ბრძანება — თუ შეცდომას
გამოიტანს, სწორედ ეს არის მიზეზი, თუნდაც თავად გამოთვლის გვერდი ერთი
შეხედვით ტვირთვას განაგრძობდეს.

## სახლთა სისტემის შესახებ

გამოთვლის სიზუსტისთვის გამოიყენება `astronomy-engine` (მაღალი სიზუსტის, თანამედროვე
ალგორითმებზე დაფუძნებული ბიბლიოთეკა). Ascendant/MC ფორმულები ამ პროექტში
დამოწმებულია რეალურ მზის ამოსვლა/კულმინაციასთან შედარებით და ემთხვევა.
რეალიზებულია ოთხი სახლთა სისტემა: **Placidus** (ნაგულისხმევი — დასავლურ
ასტროლოგიაში ყველაზე გავრცელებული, დღის/ღამის რკალების დროში სამ ნაწილად
დაყოფაზეა დაფუძნებული და მოითხოვს იტერაციულ გამოთვლას), **Whole Sign**,
**Equal** და **Porphyry**. Placidus-ის ფორმულა რიცხვითად დამოწმებულია
(კონვერგენცია და სახლების სწორი თანმიმდევრობა შემოწმებულია ჩრდილოეთ და
სამხრეთ ნახევარსფეროების, ეკვატორისა და მაღალგანედიანი წერტილების ნიმუშებზე).
პოლარული წრის მახლობლად (სადაც Placidus მათემატიკურად განუსაზღვრელი ხდება)
სისტემა ავტომატურად უბრუნდება Equal სისტემას.

## რუკის ვიზუალიზაცია

ნატალური რუკის გამოთვლის შემდეგ ჩნდება წრიული დიაგრამა (SVG) — ზოდიაქოს რგოლი,
სახლების ცუსპები, ASC/MC/DESC/IC ღერძები და პლანეტების სიმბოლოები რეალურ
პოზიციებზე. ინტერპრეტაციაში ასევე შედის „რუკის ხასიათის" ანალიზი — სტიქიათა
(ცეცხლი/მიწა/ჰაერი/წყალი) და ხარისხთა (კარდინალური/ფიქსირებული/ცვალებადი)
განაწილება, რაც პროფესიულ ასტროლოგიურ ანალიზში სტანდარტული ელემენტია.

## შემდეგი ბუნებრივი ნაბიჯები

- **კაბინეტის მართვა** — ელფოსტის/პაროლის ცვლილება, პაროლის აღდგენა და ანგარიშის წაშლა
  ერთჯერადი ელფოსტის დადასტურების ბმულებით.
- **სინასტრიისა და ტრანზიტისთვისაც** ვიზუალური დიაგრამის დამატება (ახლა მხოლოდ ნატალურს აქვს).
- **გადახდები**, თუ გსურთ ნაწილი ინტერპრეტაციისა ფასიანი გახადოთ.
